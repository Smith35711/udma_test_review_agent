# 检视质量评测记录

状态：**搁置**（2026-09-15 起）。本文记录已做完的部分与未决事项，便于日后接续。

## 1. 目的与做法

用一份**有人工标准答案的测试项目**衡量 agent2 的检视质量，并据此定向优化提示词。

- 测试目标：`/home/gzq/langgraph/test_project`（6 个模块 / 325 行）
- 标准答案：`agent2/eval/expected_defects.md`——**32 处植入缺陷** + **8 处诱饵**
- 比对口径（写在标准答案开头）：命中看「是否指出该处存在该类问题」，同一处拆多条或同类合并均算命中；等级允许 ±1 级；诱饵被报即计误报。
- 实跑方式：6 模块并行（自动并发 4），`--stages arch,review`，模型 `deepseek-v4.1-flash`。

测试项目原先只有 3 个模块（buffer / parser / resource），本次新增 3 个：`ring`（环形缓冲区）、`config`（配置解析）、`session`（会话与引用计数），缺陷覆盖内存、边界整数、字符串、接口契约、并发、错误处理、逻辑七类。诱饵是刻意放入的"看着可疑但正确"的写法（无符号减法判大小、判满用 `>=`、`sscanf` 宽度限制、`snprintf` 的 sizeof 用法等）。

## 3. 第二轮做的提示词优化（仅改检视提示词）

每条改动都由第一轮的漏检反推而来，不是泛泛加字：

| 第一轮漏检 | 反推出的原因 | 改法 | 效果 |
| --- | --- | --- | --- |
| `ring.c:56` 容量加法回绕 | 清单只说"溢出后用于分配"，未覆盖容量增长算式及其连锁后果 | 2.2 新增「容量增长算式」，点明回绕会让下标与取模基数失效 | ✅ 命中 |
| `session.c:27` 引用计数非原子 | 清单只有"数据竞争"这类宏观项，缺复合操作视角 | 2.5 新增「复合操作的原子性」 | ✅ 命中 |
| `parser.c:14` 无终止符 | 清单只有"终止符缺失"泛指，未覆盖"字符数组用满即不再是字符串" | 2.3 新增「定长字段被恰好填满」 | ✅ 命中 |
| `buffer.h:6` 契约缺失 | 第四节把"契约已保证"的豁免放得太宽，没要求契约真的写出来 | 第四节第 3 条改为：只有参数名或注释写明了前置条件才不报 | ➖ 仍漏，但报出了同文件另一处契约缺失 |

同时在第四节末尾补了**反向约束**：豁免的作用是压噪音不是压隐患，与内存安全、生命周期、边界相关的隐患与接口契约缺失仍要报（等级可判低），判据是"能否被源码证实"而非"今天会不会出事"。这句是为了防止"往多报方向推"把精确率（100%、诱饵零命中）拖下来——实测守住了。

**反驳提示词一字未改**：第一轮它 24 维持 + 1 待确认、无错驳，没有证据支持改。

## 4. 已知短板（两轮一致）

- **并发只停在"全局变量"这一层**。两轮合计抓到的并发项不是同一批：第一轮报了全局竞态漏了引用计数，第二轮报了引用计数漏了全局竞态。逐字段的非原子读改写、单字段无同步写，始终抓不全。
- **"不直接导致当下崩溃"的隐患被系统性放过**：`malloc(0)` 边界、`copy_name` 缺容量参数、循环内同一源地址。第二轮已通过反向约束改善了一部分（多报出 2 条契约类缺陷），但没根治。

## 5. 未决事项

1. **评测方法本身的硬伤：每版提示词只跑了一轮**，而单轮波动（±2 条）与改动效果（+3/−2）同量级，所以"净召回 +1"这个结论不可信。可信的只有三条定向命中（机制清楚）。要分辨真实回归与跑批波动，需**每版跑 3 轮取均值**（三倍成本，约 48 万 token/版）。
2. **把比对自动化**：目前是人工核对比对表。可以写脚本按标准清单的行号匹配，自动算召回、精确率、定级偏差，以后改提示词就能秒出对比。
3. **两条"上一版能抓、这一版丢了"的回归项**待复现确认：`session.c:16`（全局 `g_current`/`g_count` 无同步）、`buffer.c:12`（`malloc(0)` 后写 `p[0]`）。可能只是跑批波动，也可能是 2.5 节重点转移造成的注意力挤占。
4. **一处新引入的张力待决策**：第二轮检视提示词要求"隐患也要报"，而反驳规则里有"后果被夸大 → 反驳"。第二轮 `parser.c:14`（无终止符）被判反驳，理由是该字段在本模块内只写不读、记录随后被 free、没有可达后果——**核过源码它是对的，是我拟清单时判严了**。当前倾向保留这个张力（检视提议、反驳要求可达性，是该流水线的设计目的），但未最终决定。
5. 标准答案已补入 2 条由报告发现、我拟清单时漏掉的真实缺陷（`ring.c:61` 取模基数错位、`resource.h:4` 返回值语义歧义），共累计 3 条（另一条为 `buffer.h:7` 所有权声明缺失）——说明这份清单本身仍在收敛。
